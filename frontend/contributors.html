🚀 How To Contribute

🍴 Fork Repository

Create your own copy of the E-Library project by clicking the Fork button on GitHub. Forking creates a personal copy of the repository under your GitHub account, so you can freely experiment and make changes without affecting the original project. Think of it as your own playground! 🎮

Steps:
1. Go to the E-Library GitHub repository
2. Click the "Fork" button at the top right corner
3. GitHub will create a copy under your account
4. You now have your own version to work on!

🌿 Create Branch

Never work directly on the main branch! Always create a new branch for every feature or bug fix you work on. This keeps your changes organized and makes it easier for maintainers to review your work.

Steps:
1. Clone your forked repo to your computer:
git clone https://github.com/your-username/e-library.git

2. Navigate into the project:
cd e-library

3. Create and switch to a new branch:
git checkout -b feature/your-feature-name

Examples:
git checkout -b feature/dark-mode
git checkout -b fix/search-bug
git checkout -b docs/readme-update

💻 Make Changes

Now the fun part — start coding! Implement your feature, fix a bug, improve the UI, or update the documentation. Make sure your changes are clean, well-tested, and follow the project's coding style.

Steps:
1. Make your changes in VS Code or your preferred editor
2. Test everything thoroughly before committing
3. Stage your changes: git add .
4. Commit with a clear message: git commit -m "Add: dark mode toggle feature"

Good commit message examples:
✅ "Fix: search bar not working on mobile"
✅ "Add: reading progress bar feature"
✅ "Update: improved PDF card design"
❌ "fixed stuff"
❌ "changes"

🚀 Submit Pull Request

You're almost there! Push your branch to GitHub and open a Pull Request so the maintainers can review your code and merge it into the project.

Steps:
1. Push your branch to GitHub:
git push origin feature/your-feature-name

2. Go to the original E-Library repository on GitHub
3. Click "Compare & pull request"
4. Add a clear title and description of what you changed
5. Submit the Pull Request!

Tips for a good PR:
⭐ Describe what you changed and why
⭐ Add screenshots if you changed the UI
⭐ Keep it focused — one feature per PR
⭐ Be patient — maintainers will review and give feedback
⭐ Respond to comments and make requested changes
